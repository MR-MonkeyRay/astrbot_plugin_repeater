# AstrBot 自动复读插件

为 AstrBot 群聊提供按群独立的自动复读、随机打断与可选 LLM 智能打断、智能禁言提示功能。

## 功能

- 按连续的规范化消息链判重；文本、图片、QQ `face` 与 OneBot `mface` 都参与匹配，普通复读按原顺序回发。
- 图片优先按 `file` 匹配，缺失时使用 URL；`face` 使用表情 ID，`mface` 优先使用表情包和表情 ID。
- 同一连续序列中，同一用户只计一次；连续序列计数只保存在内存中，重启后重新计数。
- 同一内容被复读或打断后进入冷却期（`repeat.cooldown_seconds`，默认 30 分钟），冷却结束后可再次触发；每群最多保留 256 条冷却记录。
- 打断已启用且达到 `interrupt.threshold` 时，先按 `interrupt.probability` 尝试打断；未触发打断且普通复读已启用并达到 `repeat.threshold` 时，再按 `repeat.probability` 尝试普通复读。
- 智能打断在非取消的解析、配置、请求、响应失败或超过 `intelligent_provider.timeout_seconds` 时使用静态打断文案。
- 写入提示词的被复读内容最多 200 字并以标签包裹、声明不执行其中指令；用户昵称最多 32 字；LLM 回复最多 300 字。
- 禁言仅支持 OneBot v11（`aiocqhttp`）平台，且仅在打断消息发送成功后检查：全局开启且群未禁用时先按 `mute.probability` 判定，命中后机器人须为群主或管理员才调用禁言；禁言成功后可发送智能或静态提示。各跳过原因都会写日志（未启用、平台不支持为 debug 级，未命中概率为 info 级，机器人无权限为 warning 级）。
- 顶替禁言：命中禁言概率但触发用户是群主或群管理员时，不禁言他，改为登记一次顶替禁言，由本群下一位发言的普通成员（发任意消息都算，不限复读内容）100% 兑现，并发送专属提示（开启智能禁言提示时由 LLM 按 `intelligent_mute.proxy_prompt` 生成，否则或失败时使用 `mute.proxy_texts`）。每群同时最多一次待兑现，不叠加；登记会持久化，重启后仍然有效，直到兑现为止。禁言关闭时既不登记也不兑现，已有的登记会被直接丢弃；无法获取群信息、机器人无权限或禁言 API 失败时只在日志中记录警告，本次顶替作废。
- 只有命中复读、打断，或登记、兑现顶替禁言时才写入插件存储：发送前先持久化待发送标记。明确的发送失败或主打断生成取消会尝试回滚；回滚失败、发送协程取消、发送成功但提交保存失败等结果不确定情形会继续抑制重复触发。
## 指令

所有指令仅在群聊中可用，并受 AstrBot 的唤醒前缀规则约束。

| 指令 | 说明 | 权限 |
| --- | --- | --- |
| `自动复读 查看` | 查看本群状态、最小复读触发人数和概率。 | 所有成员 |
| `自动复读 开启` | 开启本群自动复读。 | AstrBot 管理员、当前群群主或群管理员 |
| `自动复读 关闭` | 关闭本群自动复读。 | AstrBot 管理员、当前群群主或群管理员 |
| `自动复读 帮助` | 显示帮助。 | 所有成员 |
| `repeatMsg` | `自动复读` 的英文别名。 | 与对应子命令相同 |
| `打断复读 查看` | 查看本群打断状态、有效禁言配置和待兑现的顶替禁言。 | 所有成员 |
| `打断复读 开启` | 开启本群打断复读。 | AstrBot 管理员、当前群群主或群管理员 |
| `打断复读 关闭` | 关闭本群打断复读。 | AstrBot 管理员、当前群群主或群管理员 |
| `打断复读 帮助` | 显示帮助。 | 所有成员 |
| `interruptRepeat` | `打断复读` 的英文别名。 | 与对应子命令相同 |

群聊中，未授权用户执行 `开启` 或 `关闭` 时会收到权限错误提示。
## 配置

配置 Schema 位于 `_conf_schema.json`；下文的“页面范围”指 AstrBot WebUI 滑块。

### 复读与打断

| 字段 | 默认值 / 范围 | 说明 |
| --- | --- | --- |
| `repeat.default_enabled` | `true` | 未单独设置的群默认开启普通复读。 |
| `repeat.disabled_group_ids` | `[]` | 关闭普通复读的群号；开关指令会更新并持久化。 |
| `repeat.threshold` | `3`；页面 `3`–`50`，运行时 `≥3` | 普通复读所需的独立用户数，含首位发送者。 |
| `repeat.probability` | `0.3`；`0`–`1` | 普通复读概率。 |
| `repeat.cooldown_seconds` | `1800`；`60`–`86400` 秒 | 同一内容复读或打断后的冷却时长，普通复读与打断共用。 |
| `interrupt.default_enabled` | `true` | 未单独设置的群默认开启打断复读。 |
| `interrupt.disabled_group_ids` | `[]` | 关闭打断复读的群号；开关指令会更新并持久化。 |
| `interrupt.threshold` | `3`；页面 `3`–`50`，运行时 `≥3` | 打断所需的独立用户数，含首位发送者。 |
| `interrupt.probability` | `0.1`；`0`–`1` | 打断概率。 |
| `interrupt.texts` | 预置 5 条 | 静态打断文案；配置项为空时使用内置 `打断！`。 |

### 打断后禁言

| 字段 | 默认值 / 范围 | 说明 |
| --- | --- | --- |
| `mute.enabled` | `false` | 是否启用打断后禁言。 |
| `mute.disabled_group_ids` | `[]` | 不执行禁言的群号。 |
| `mute.probability` | `0.05`；`0`–`1` | 打断成功后的禁言概率。 |
| `mute.duration_min` / `mute.duration_max` | `1` / `15` 秒；各为 `1`–`3600` 秒 | 随机禁言时长的下限和上限。 |
| `mute.texts` | 预置 5 条 | 静态禁言提示，支持 `{user}` 和 `{time}`；配置项为空时使用内置文案。 |
| `mute.proxy_texts` | 预置 4 条 | 静态顶替禁言提示，支持 `{user}`（顶替者）、`{time}` 和 `{admin}`（免于禁言的群管）；配置项为空时使用内置文案。 |

### LLM供应商配置

| 字段 | 默认值 / 范围 | 说明 |
| --- | --- | --- |
| `intelligent_provider.mode` | `"astrbot"` | 共享LLM供应商接入方式：`"astrbot"` 或 `"openai_compatible"`。 |
| `intelligent_provider.provider_id` | `""` | 仅 AstrBot 模式使用；留空且有触发会话时，运行消息会跟随该会话，LLM调用测试必须选择明确供应商。 |
| `intelligent_provider.manual_api_base` | `""`；最多 256 字符 | 仅直连模式使用；须为带主机的 `http`/`https` URL，不能含账号、密码、查询串或片段。 |
| `intelligent_provider.manual_api_key` | `""`；最多 512 字符 | 仅直连模式使用；保存在插件配置中。 |
| `intelligent_provider.model` | `""` | 直连模式必填；AstrBot 模式可选，用于覆盖供应商模型。 |
| `intelligent_provider.timeout_seconds` | `15`；`1`–`120` 秒 | 单次生成的最长等待时间，超时后使用静态文案，并在调用记录中标记 `timeout`。 |
| `intelligent_interrupt.enabled` / `intelligent_mute.enabled` | `false` | 分别启用智能打断和智能禁言提示；后者同时控制智能顶替禁言提示。 |
| `intelligent_interrupt.prompt` / `intelligent_mute.prompt` / `intelligent_mute.proxy_prompt` | 内置默认提示词 | 分别用于智能打断、智能禁言提示和智能顶替禁言提示（调皮播报替罪羊）；为空或非法值时回退到对应内置提示词。 |

## 复读机控制台

在 WebUI 的复读机插件中打开 **复读机控制台**。

- LLM调用测试不受两个智能功能开关影响，使用固定模拟输入；结果返回当前页面，并在历史存储可用时写入一条 `manual_test` 记录。测试不会发送群消息、调用禁言 API 或修改复读状态。
- AstrBot 模式下，留空 `provider_id` 的运行消息会跟随触发会话；LLM调用测试必须先保存明确的供应商。直连模式需要 API Base URL、API Key 和自定义模型 ID；缺项测试会报错且不发起直连请求。
- API Key 留空保存会保留现有值，填写新值会替换，点击“清除 Key”会删除。插件自身的页面响应、历史字段和日志路径不会主动记录或回显 Key；能访问插件配置的人员仍可读取已保存的 Key。
- 保存 `intelligent_provider` 时通过 AstrBot 的 `save_config_async` 写入，成功后立即更新运行时设置，并保留该分组中页面未管理的字段（如 `timeout_seconds`）；其他配置按 AstrBot 的插件配置或重载流程生效。

## 升级说明

- v1.7.0 起，旧版“已复读后永久不再触发”的指纹会在首次加载时迁移为冷却记录，到期后自动清除；连续序列计数不再持久化。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `main.py` | 插件入口：事件与指令处理、禁言、Page 路由注册、调用记录调度、停机排空。 |
| `repeater_service.py` | 复读状态机、冷却表与发送事务（pending → 提交/回滚）。 |
| `repeater_messages.py` | 消息链规范化与判重指纹。 |
| `repeater_config.py` | 配置校验、运行时设置及通过 AstrBot 公开接口保存配置。 |
| `llm_client.py` | LLM 调用（AstrBot 供应商或 OpenAI 兼容直连）、超时与输入输出裁剪。 |
| `web_console.py` | 复读机控制台的 Page Web API。 |
| `intelligent_history.py` | 七日调用记录存储。 |

## 记录与隐私

- 调用记录按本地日期追加写入插件数据目录中的 `intelligent_history-YYYY-MM-DD.jsonl` 文件；写入失败时会截断回写入前的大小。存储可用时，运行时会异步记录LLM调用元数据、群和禁言上下文、输入提示与回复；记录写入失败不会阻断消息投递。
- 记录可能包含群消息和提示中的用户信息；能够访问控制台的人员应视为可读取这些内容。历史字段不保存 API Base URL 或 API Key。
- 页面默认展示近 24 小时调用记录，可切换 2、3 或 7 天，并按类型筛选或分页；这些时间范围均为滚动窗口。
- 存储可用时，“清理调用记录”会删除插件数据目录中所有当前保留的调用记录，而非仅当前筛选或时间范围内的记录；此操作不可撤销。
- 存储不可用或记录文件无法读取时，读取和清理会显示失败；修复存储后可重试。
- 严格早于七天的记录会在初始化和之后每小时的清理任务中删除。
